# GROBID HTTP and service parity audit

**Baseline:** `grobidOrg/grobid` commit `f313f7010773fe8113cbb0f7a774960450a850d0`. **Evidence:** static inspection of the pinned Java source. **Runtime validation:** not performed. No Java server, model inference, Rust candidate, or HTTP probes were run for this audit.

## Inventory and scope

`api-inventory.json` is the machine-readable contract inventory. It records 45 active annotated resource handlers: 44 in `GrobidRestService` and one in `HealthResource`. They cover **28 distinct application paths and 38 method/path pairs**, including seven additional media-negotiated handlers. Counts by HTTP annotation: GET 6, POST 26, PUT 12, DELETE 1. These counts exclude framework-generated HEAD/OPTIONS behavior, static assets, admin servlets, and commented-out routes. The Java application mounts Jersey at `/api/*`; static assets are mounted separately at `/`. [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/main/GrobidServiceApplication.java#L47-L115).

## Declared defaults versus effective behavior

| Concern | Source-observed contract and parity consequence |
|---|---|
| Page ranges | Header XML and BibTeX bind `start=0`, `end=2`. Fulltext and fulltext-with-assets bind `start=-1`, `end=-1`. Header+funding has no page fields. Preserve the raw values at the API boundary and characterize core range semantics separately. |
| Boolean-like fields | The resource accepts exactly string `1` or lowercase `true`; absent/default `0`, uppercase `TRUE`, and other strings are false. This covers raw fields, IDs, sentence segmentation, figures/tables, debug, and incremental. Do not substitute a broader Rust boolean parser. |
| Consolidation | Absent and unparsable values become 0; parseable Java `int` values pass through with no range validation here. Downstream behavior for negative or unusually large levels needs probes. |
| Repeated fields | `teiCoordinates` is a list of multipart values, accepted without a resource-layer allowlist. Citation-list inputs are repeated URL-encoded `citations` values. Scalar/duplicate conflicts need runtime characterization. |
| Single citation naming | Single citation input is also named **`citations`**, despite being bound to one String. Patent text input is **`input`**, while funding uses **`text`**. |
| BLANK fulltext | The ordinary fulltext resource identifies BLANK flavor and calls the blank processor with IDs=false, sentences=false, and empty coordinates, regardless of the request; other consolidation/raw/debug fields do not reach this branch. Assets use a different helper and have no equivalent BLANK shortcut. |
| Assets flag swap | Both assets resource methods pass raw fields as affiliations, citations, copyrights; the private helper declares affiliations, copyrights, citations. Consequently the effective copyright and citation flags are interchanged. Record an intentional compatibility decision before correcting it. |
| Header BibTeX | It has no discarded-text binding and explicitly forwards false. XML accepts the field. |
| Training architecture | `modelTraining` declares default `crf` but the processor does not use its architecture argument to select the trainer. Model download separately defaults missing/empty architecture to `crf`. |
| Annotation type | Integer 0→citations, 1→blocks, 2→figures; other integers map to null. The primitive field has no explicit `@DefaultValue`; missing/invalid binding is an oracle probe rather than a guessed contract. |

## Media negotiation, serialization, and error paths

**Media selection is part of parity.** Header, citation, citation-list, and references have XML and BibTeX handlers sharing method/path. The explicit BibTeX server quality of 0.5 is intended to prefer XML when Accept is absent. Exercise absent Accept, `*/*`, XML/BibTeX priorities and q-values, unsupported types, and debug requests under each negotiated handler. Actual Jersey behavior has not been observed. [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/util/BibTexMediaType.java#L18-L23).

**Debug mode changes the response representation.** Header, fulltext, assets, and references can return text/plain UTF-8 model-labeling sections, replacing XML/BibTeX/ZIP output. Empty captures or a filter excluding every captured model return 204. `models` is a comma-separated, trimmed, lowercased, deduplicated enum-name allowlist; unknown names throw a 400 service exception. The filter is validated outside the processor try/catch, so it can reach the JSON mapper while other errors are caught locally. Output retains capture order and occurrence numbering, including terminal newlines. The BLANK fulltext branch bypasses this behavior. [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessFiles.java#L77-L96) [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessFiles.java#L170-L182) [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/util/GrobidDebugUtils.java#L65-L138).

**Text endpoints are not one uniform serializer.** Date/header-name/citation-name processors replace LF and TAB with spaces and emit concatenated TEI fragments as text/plain; affiliations only replace TAB, preserve LF, and wrap multiple results in `<xml>`. A nonnull empty affiliation list can produce an empty wrapper rather than 204. Citation parsing deliberately does not apply the commented-out whitespace normalization. Funding acknowledgement advertises text/plain but explicitly builds successful responses as application/json UTF-8. [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessString.java#L66-L266) [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessString.java#L283-L317) [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessString.java#L465-L498).

**Citation collections and PDF references need separate fixtures.** Citation-list XML constructs a full TEI envelope and substitutes `<biblStruct xml:id="bN"/>` for null entries; BibTeX uses a placeholder `@misc` with bN for null entries but generated keys for nonnull entries. PDF references use their own envelope and `BibDataSet.toTEI` indexing. Keep sequence order, identifiers, raw citations, escaping, namespaces, and separators visible to the comparator. [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessString.java#L334-L401) [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessFiles.java#L989-L1037).

**There is no single error-envelope contract.** Many processors catch pool exhaustion (`NoSuchElementException`) and return a bare 503. File processors generally catch other exceptions and return 500 with the exception message; string processors generally return a bare 500. Even an explicit `GrobidServiceException` thrown inside these broad try blocks can be converted to 500. Training methods have distinct service-exception catches preserving their statuses. Thus a global translation of every timeout or bad input into a polished JSON error would diverge. [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessFiles.java#L243-L255) [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessString.java#L94-L103) [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessTraining.java#L226-L234).

## Training lifecycle and observable mismatches

1. `modelTraining` creates a token, gets a trainer, and atomically claims the lowercased model key. A concurrent training for the same key returns 409; flavor-specific model names have distinct claims. It creates `training-history/<token>`, writes `ongoing`, registers the Future/maps before starting a dedicated executor, and immediately returns 200 JSON token. The request does not wait for training. [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessTraining.java#L248-L339).
2. Worker modes are full, holdout, split, and nfold. Full produces no evaluation report; holdout trains then evaluates; split uses ratio; nfold rejects n=0 in the worker. Unsupported mode is also a worker failure, so a request can receive a token and fail asynchronously. Worker success writes done and writes report.txt only when results are nonnull; failures write failed or killed. Finally removes the owner-checked model claim and token maps. [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessTraining.java#L380-L436).
3. `allTraining` reports the in-memory live registry. It deliberately does not report stale on-disk ongoing entries after restart; ordering follows concurrent-map keys and should be probed rather than assumed. [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessTraining.java#L440-L461).
4. `killTraining` rejects blank/path-containing tokens and missing token directories, attempts `Future.cancel(true)`, marks stale ongoing states killed, and releases only a claim owned by that token. The code explicitly warns that Wapiti/DeLFT/native training may continue after JVM thread interruption. A reported killed status therefore does not prove the model file is no longer being written. Rust should isolate and terminate worker process groups and specify any externally visible compatibility difference. [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessTraining.java#L464-L540).
5. `trainingResult` returns 200 for ongoing; for any other status it requires report.txt or returns 400. Consequently failed, killed, and successful full training without a report can become 400 instead of a JSON status. A missing status with a report can produce a string status `null`. Capture these state combinations explicitly. [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessTraining.java#L552-L622).
6. Model download defaults missing/empty architecture to crf, lowercases model names and replaces hyphens with slashes, checks model existence, and emits `model.wapiti` for CRF or selected .hdf5/.json/.pkl/.txt files for other architectures. GET declares form consumes despite reading query parameters. Returned archive is `model.zip`. [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/process/GrobidRestProcessTraining.java#L130-L238) [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-service/src/main/java/org/grobid/service/GrobidRestService.java#L1022-L1040).

### Evidence limits and handoff

This audit establishes declarations and source-visible control flow, not a guarantee of exact wire behavior or performance. The highest-priority oracle probes are media negotiation, primitive/multipart binding failures, the assets flag swap, BLANK/debug behavior, funding Content-Type, annotation null cleanup, and training cancellation/results. Stock configuration has concurrency 10 and a one-second pool wait; saturation alone can produce 503 independently of Java-versus-Rust CPU cost. [source](https://github.com/grobidOrg/grobid/blob/f313f7010773fe8113cbb0f7a774960450a850d0/grobid-home/config/grobid.yaml#L75-L81).

Keep captured upstream bugs separately classified from intended functionality. Public output quirks may need a compatibility mode; leaks, unsafe paths, and runaway native workers should receive an explicit documented deviation and a regression test. Do not claim perfect parity until the complete route/parameter/profile/corpus matrix and runtime questions in the JSON inventory are resolved.
